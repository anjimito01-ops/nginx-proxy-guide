# 蒼陵イレブン

ファミコン時代の「コマンド選択式サッカー」の手触りを、現代の Android スマホ向けに作り直した 2D サッカーゲームです。

**TypeScript + Phaser 3 + Capacitor** で作られており、開発中はブラウザでそのまま遊べて、
最終的に同じコードがそのまま Android アプリ（APK）になります。

> 登場するチーム・選手・必殺技はすべてオリジナルです。実在の作品・団体・人物とは関係ありません。

---

## 遊びかた

ボールを持つと画面下部にコマンドウィンドウが出ます。相手ゴールへ迫ってシュートを決めてください。

| コマンド | 内容 |
| --- | --- |
| ドリブル | 1 ゾーン前進する。前にいる相手と 1 対 1 の勝負になる |
| パス | 味方へつなぐ。パスコースに相手がいるとカットされる |
| シュート | ゴールを狙う。距離が遠いほど威力が落ちる |
| キープ | その場でためる。ガッツが 8 回復する |

### ガッツ

各選手は「ガッツ」を持っています。行動するたびに消費し、**残量が減ると能力そのものが落ちます**。
必殺技はガッツを大きく消費するので、どこで切るかが勝負どころです。ハーフタイムで一部回復します。

### 必殺技

エース級の選手だけが持っています。コマンドを選ぶと技の一覧が出ます。

- **ファントムシュート**（天羽 翔）— GK を打ち抜く必殺シュート
- **疾風ステップ**（天羽 翔）— 突破力を大きく上げるドリブル
- **ライジングアーク / スレッドパス**（藤堂 悠真）— 司令塔の飛び道具
- **アイアンカット**（岩瀬 鉄平）— 守備時に自動で発動
- **グラビティホールド**（神無月 護）— GK が自動で発動するセービング

相手 GK も必殺セービングを持っているため、必殺シュートが必ず入るわけではありません。

### 駆け引きのコツ

- コマンドの「ドリブル」欄には **前に立ちはだかる相手の名前** が出ます。相手が強ければパスで散らす
- ドリブルで **GK をかわす** と、次のシュートはほぼ決まります（ハイリスク・ハイリターン）
- 遠距離シュートは弾かれやすい。こぼれ球に詰められる位置かどうかも考える

## 開発

### 必要なもの

- Node.js 20 以上
- APK をビルドする場合のみ: Android Studio（JDK 17 + Android SDK）

### ブラウザで遊ぶ / 開発する

```bash
npm install
npm run dev
```

表示された URL を開けばすぐ遊べます。`--host` 付きで起動しているので、
同じ Wi-Fi 上のスマホから PC の IP アドレスで開けば実機の操作感も確認できます。

### 検証

```bash
npm run typecheck   # 型チェック
npm test            # ゲームロジックの単体テスト
npm run build       # 型チェック + 本番ビルド
```

### Android アプリとしてビルドする

```bash
npm run cap:sync    # ビルドして android/ へ反映
npm run cap:open    # Android Studio で開く
```

あとは Android Studio で `Run` すれば実機・エミュレータで動きます。
配布用の APK は `Build > Generate Signed Bundle / APK` から作成してください。

## 構成

```
src/
├── core/          ゲームロジック（Phaser 非依存・単体テスト対象）
│   ├── types.ts     型定義
│   ├── rng.ts       シード固定できる乱数生成器
│   ├── rules.ts     1 対 1 / シュート / パスの判定式
│   ├── match.ts     試合進行エンジンと CPU の思考
│   └── match.test.ts
├── data/
│   └── teams.ts   チーム・選手・必殺技のデータ
├── ui/            描画部品（スコアボード、ピッチ、コマンドUI ほか）
└── scenes/        Phaser のシーン（タイトル / 試合 / 結果）
```

### 設計方針

- **ロジックと描画を完全に分離**。`src/core` は Phaser を一切 import せず、
  試合エンジンは「状態」と「何が起きたか（`MatchEvent` の列）」だけを返します。
  演出はシーン側がそのイベント列を読んで再生するだけなので、
  バランス調整を単体テストとシミュレーションだけで回せます。
- **画像アセットを持たない**。選手やボールのドット絵は起動時にコードで生成しているため、
  リポジトリにバイナリがなく、APK も軽く保てます。
- 乱数はシード固定できるので、同じ試合展開を何度でも再現できます。

### 試合のモデル

ピッチを **縦 5 ゾーン × 横 3 レーン** に抽象化しています。
ボール保持者だけが動き、他の選手はフォーメーション上の定位置にいます。
ゾーン 0 が自陣ゴール、ゾーン 4 が相手ゴールで、1 コマンド＝試合時間 2 分、前後半 45 分ずつです。
